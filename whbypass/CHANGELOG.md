# WHBypass 更新日志

## 1.0.0

首个发布版。目标 App 国家网络身份认证（`cn.cyberIdentity.certification`）1.2.38，在 rootless 越狱（Dopamine + ElleKit）环境下不再一打开就闪退，首页 → 管理 → 我的 → 网号网证申领 → 同意协议 → 证件类型选择全程可交互，连续三次冷启动验证通过。

- **闪退根因**：主程序里有 6 个"炸弹函数"（`WHClient+0x148470`、`+0x1484d0`、`+0x149db8`、`+0x14a1b0`、`+0x14a4cc`、`+0x14a7dc`）。函数体把 `sp` 和 `lr` 一起改成上下文里的值（实测是 `0x1`），再用两条 `mov`+`movk` 拼出两个立即数相加，`br` 到这个和上——和落在 `0xb5a0X000`，也就是 App 的 `__PAGEZERO` 保留区，进程无法在那里映射任何内存。执行即崩，且不留任何可回溯的栈。
- **调用路径**：这 6 个地址在全二进制里没有一条 `bl` 指向它们，只被 6 处 `adrp`+`add` 写进 block 的 `invoke` 字段（`+0x144334`、`+0x144638`、`+0x1455f0`、`+0x149d14`、`+0x14a428`、`+0x14a738`），由 `0x13f000`～`0x145000` 那段混淆状态机 `dispatch_async` 到全局队列。
- **主要手段是改掉这 6 个入口**：把第一条指令换成 `ret`。block 照常投递、照常结束，只是不再跳。启动期异常从 1 次降到 **0 次**，因此不再需要接管 Mach 异常端口、关掉 KSCrash、拦截 `thread_suspend`——0.1.66 时期那套"接住后果"的机制全部关掉了。
- **辅助手段是掐掉反调试守卫**：`WHClient+0x1406b0` 是 `getpid()` + `ptrace(PT_DENY_ATTACH)` 的带重入计数入口。把开头两条指令换成 `mov x0,#0; ret`。炸弹修好之后这一条仍然需要：关掉它时两次启动都在 45 秒内静默退出，日志里没有任何异常记录。
- **发布版不再留日志**：日志开关改为编译期判断，`make package` 走 debug 构建带日志，`make package FINALPACKAGE=1` 走 release 构建，所有日志调用被编译掉，不会在 App 容器里创建 `gtcfg.log`。需要排查时用前者重新构建。
- **检测引擎**：梆梆安全 Everisk（`everisk_ZDAX iOS5.1.2.SP2-250207`），编译期静态链入主二进制。它的 27 个 checker 在 467ms 之后才被调度，而炸弹在更早的时候就已投递，所以短路 checker 对闪退没有作用；这些短路保留作纵深。

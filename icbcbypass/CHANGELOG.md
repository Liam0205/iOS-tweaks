# Changelog

## 1.1.2

修复「点很多次才响应一次」的根因：不再拦截主线程上对 `-[UIView setUserInteractionEnabled:NO]` 的调用。

- 原来的做法是启动 3 秒后无条件拦掉所有「关闭交互」的调用，用来对抗「后台线程反复关闭交互」这个假设。
  在 3.1.50 上抓调用栈发现，被拦到的全部是主线程上 UIKit 自己的调用——`UILabel`、
  `_UIVisualEffectBackdropView`、`_UIBarBackgroundShadowContentImageView` 这类内部子视图，
  调用栈全是 `UIKitCore`，没有一条来自 App 的冻结代码。
- 这些子视图本该是不可交互的。拦掉之后它们保持可交互，会把本该交给父级 `UIButton` 的点击吃掉，
  表现就是点击大多没有反应。
- 现在只拦后台线程发起的关闭调用，主线程一律放行。窗口和根视图的交互由解冻定时器每 2 秒重新打开，
  主线程这条路径不需要在这里挡。
- 验证：工商银行 3.1.50 登录页的「我已阅读并同意」勾选框，1.1.1 上连点 3 次全部无反应，
  1.1.2 上连点 3 次全部生效；静置 75 秒后底部 tab 切换仍然即时响应。
